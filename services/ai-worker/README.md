# Reel Studio — AI Worker Service (Phases 1, 2 & 3)

This service provides the core AI audio-processing, speech recognition, technical terminology normalization, and **intelligent highlight selection** pipeline for **PS04 Reel Studio**.

---

## 1. Complete Pipeline Architecture

```text
Input Video (.mp4 / .mkv)
       │
       ▼
[MediaProbeService] ──> Validates presence of audio, video resolution, FPS, duration
       │
       ▼
[AudioExtractorService] ──> FFmpeg extraction to 16kHz Mono 16-bit PCM WAV (cached)
       │
       ▼
[TranscriberService] ──> faster-whisper (CTranslate2 INT8 CPU) with word-level timestamps
       │
       ▼
[TermNormalizerService] ──> N-gram context-aware technical terminology replacement
       │
       ▼
Validated Transcript JSON (storage/transcripts/<name>.json)
       │
       ▼
[HighlightSelectorService] (Phase 3)
       │  ├── 1. Sentence boundary segmentation (. ! ? ; : and pauses >= 0.65s)
       │  ├── 2. Candidate window generation (30s - 60s target duration)
       │  ├── 3. Multi-signal heuristic educational scoring (Info, Hook, Coherence, Ending, Density)
       │  └── 4. Word-aligned boundary refinement and validation
       ▼
Highlight Result JSON (storage/highlights/<name>_highlight.json)
```

* **Operating System:** Windows 10/11 or Linux
* **Python:** 3.10+ (Tested on Python 3.13.2, 64-bit Windows)

* **Dependencies:** `faster-whisper`, `ctranslate2`, `pydantic>=2.0`, `pydantic-settings`, `pytest`

## 3. Command-Line Interface (CLI)

The CLI provides two primary subcommands: `transcribe` and `select-highlight`.

### A. Transcription (`transcribe`)
Extracts audio and produces a validated word-level transcript with technical terminology normalization:
```powershell
python -m app.cli transcribe --input "path/to/lecture.mp4"
```

Options:
| Flag | Description | Default |
| :--- | :--- | :--- |
| `-i`, `--input` | Path to source video (.mp4) or audio (.wav) | *Required* |
| `-m`, `--model` | Whisper model (`tiny`, `base`, `small`, `medium`) | `small` |
| `--device` | Inference device (`cpu`, `cuda`) | `cpu` |
| `--compute-type` | Model quantization (`int8`, `float32`) | `int8` |
| `-l`, `--language`| Language code (e.g. `en`) | Auto-detect |
| `-o`, `--output` | Custom destination file or directory | `storage/transcripts/` |
| `--limit-sec` | Optional duration cap in seconds for smoke tests | None (Full) |
| `--force` | Force re-extraction, bypassing cache | False |

### B. Highlight Selection (`select-highlight`)
Consumes a validated transcript JSON and extracts the single best 30–60-second educational highlight:
```powershell
python -m app.cli select-highlight --input-transcript "../../storage/transcripts/lecture.json" --min-duration-sec 30 --max-duration-sec 60
```

Options:
| Flag | Description | Default |
| :--- | :--- | :--- |
| `-i`, `--input-transcript` | Path to validated transcript JSON | *Required* |
| `--min-duration-sec` | Minimum clip duration in seconds | `30.0` |
| `--max-duration-sec` | Maximum clip duration in seconds | `60.0` |
| `-o`, `--output` | Custom output file path | `storage/highlights/<stem>_highlight.json` |

## 4. Phase 3 Highlight Selection Engine

### Design Principles
1. **Never select arbitrarily:** Does not pick the first 60 seconds, a random interval, or the loudest sound.
2. **100% Deterministic:** Same transcript and configuration always produces identical output.
3. **Fully Grounded in Timestamps:** Timestamps strictly correspond to actual speech tokens with natural release padding.
4. **Standalone Short-Form Value:** Finds moments that explain a core concept, analogy, or takeaway suitable for Reels, Shorts, and TikTok.

### Candidate Generation
- Words are segmented into `Sentence` units using:
  1. Terminal punctuation: `.`, `!`, `?`
  2. Clause terminators: `;`, `:`
  3. Conversational pause gaps: consecutive word gap $\ge 0.65\text{s}$.
- Sentences include post-speech trailing silence release (up to $+0.35\text{s}$ pause before next word) to prevent unnatural speech clipping.
- Candidates are generated by combining consecutive sentences whose span $D$ satisfies $\text{min\_duration} \le D \le \text{max\_duration}$.

### Multi-Signal Scoring Heuristics
Each candidate segment is evaluated across five linguistic dimensions ($0 - 100$), penalized for duration deviation, and scaled by ASR confidence:

$$\text{RawScore} = 0.30 \times S_{\text{info}} + 0.25 \times S_{\text{self}} + 0.20 \times S_{\text{hook}} + 0.15 \times S_{\text{ending}} + 0.10 \times S_{\text{density}} - P_{\text{duration}}$$

$$\text{FinalScore} = \text{RawScore} \times \left(0.90 + 0.10 \times \frac{S_{\text{conf}}}{100}\right)$$

1. **Information Value ($S_{\text{info}}$, weight 30%):**
   - Concept definitions: *"is called"*, *"concept called"*, *"we define"*, *"one big concept"*.
   - Explanations & causality: *"because"*, *"which allows us to"*, *"how it operates"*, *"speed and efficiency"*.
   - Illustrative analogies/examples: *"for example"*, *"imagine"*, *"just like"*, *"different scenarios"*.
   - Normalized technical terms: presence of verified terms audited by the terminology normalizer.
   - Core takeaways: *"trade-off"*, *"in summary"*, *"super important to know"*.
2. **Self-Contained Meaning ($S_{\text{self}}$, weight 25%):**
   - Penalizes dangling openers (*"as I mentioned earlier"*, *"like I said before"*).
   - Penalizes continuation conjunctions at boundary start (*"and so"*, *"and then"*, *"or else"*).
   - Penalizes dangling forward deferrals at boundary end (*"more on that later"*, *"in the next video"*).
3. **Opening Hook ($S_{\text{hook}}$, weight 20%):**
   - Rewards problem statements, questions, or conceptual launches (*"Before we get into..."*, *"Why do we..."*).
   - Heavily penalizes speaker self-introductions and social media fluff (*"Hi my name is..."*, *"Subscribe to my channel"*, *"I have a bachelor's and master's"*).
4. **Ending Quality ($S_{\text{ending}}$, weight 15%):**
   - Rewards clean terminal punctuation (`.`, `!`, `?`).
   - Penalizes abrupt cutoffs or trailing prepositions/conjunctions (*"and"*, *"or"*, *"with"*, *"to"*).
5. **Speech Density & Cadence ($S_{\text{density}}$, weight 10%):**
   - Ideal cadence: $2.2 - 3.6$ words per second.
   - Penalizes excessive filler words (*"um"*, *"uh"*, *"you know"*).
6. **Duration Penalty ($P_{\text{duration}}$):**
   - Small penalty for deviating from target sweet-spot (default 45s).
7. **ASR Confidence Support:**
   - Multiplies score by speech recognition certainty so garbled audio does not win.

### Short-Transcript Fallback Policy
If an input transcript's total speech duration is less than the configured `min_duration_sec` (e.g., a 15-second test snippet), the engine:
1. Returns the entire available speech duration.
2. Sets `selection_method="short_transcript_fallback"`.
3. Documents in `reason` that fallback mode was engaged.
4. Never hallucinates non-existent timestamps or crashes.

## 7. Known Limitations & Future Work

1. **Transcript-Only Scope:** Phase 3 operates strictly on linguistic and timestamp signals. It does not analyze visual scene transitions, instructor gestures, or IDE screen activity (planned for Phase 4 CV visual tracking).
2. **Audio Dynamics:** Pitch variations, vocal energy, and acoustic excitement are not currently analyzed (planned for multimodal fusion).
3. **Partial Test Video Note:** When running on `storage/transcripts/lecture.json`, the test transcript covers only the first 60 seconds of the 15-minute video. While it successfully chose the Big O definition and vehicle analogy over the speaker bio within that window, evaluating highlights across the full 15-minute video requires running full-length transcription.
